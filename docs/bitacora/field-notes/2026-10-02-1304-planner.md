## Contexto
El usuario pidio diagnosticar el #725. Es un PR de Dependabot que sube xunit.v3.mtp-v2 de 3.* a 4.* en los 16 csproj de tests/; build-and-test fallaba.

## Descubrimientos
- Causa: xunit 4 marca CollectionBehaviorAttribute.DisableTestParallelization como obsoleto con error (CS0619). Lo usan los AssemblyFixture.cs de 5 smoke tests (Sedes, Colaboradores, ControlHoras, Mcp.Comandos, Mcp.Consultas).
- Reemplazo verificado en el XML doc del paquete 4.0.1: [assembly: Parallelization(Mode = ParallelMode.None)] (Xunit.v3 / Xunit.Sdk). El default de v4 sigue siendo ParallelMode.Collections.
- El error de ReportGenerator del log es secundario: el build roto no genero cobertura.
- Programacion.SmokeTests serializa via xunit.runner.json (parallelizeTestCollections: false). No se verifico que v4 siga respetando esas claves en runtime.

## Decisiones
- Opcion 1: un issue tipo:refactor que reemplaza al PR #725 (bump + migracion del atributo + unificar Programacion.SmokeTests al mismo mecanismo). Se descarto ignorar las versiones mayores en Dependabot.
- dom: union de los dominios reales de los smoke tests (sedes, colaboradores, control-horas, programacion).

## Descartado
- Ignorar las versiones mayores de xunit en la configuracion de Dependabot (#714): solo aplaza el problema.

## Preguntas abiertas
- Si xunit 4 sigue respetando parallelizeTestCollections en xunit.runner.json (el issue lo esquiva unificando mecanismo).
