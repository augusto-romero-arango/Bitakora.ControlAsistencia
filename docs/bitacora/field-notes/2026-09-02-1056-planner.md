## Contexto
El usuario pidio crear el MCP de comandos con dos tools iniciales (registrar colaborador, registrar sede), autenticado con WorkOS. Modo explorar -> "Composicion asistida via servidores MCP". Se leyo el servidor hermano Mcp.Consultas completo (identidad #554/#540/#558/#560/#561), MEF-ADR-0047/0048, el modulo apim-mcp-api, los dos comandos HTTP y sus validadores, y el skill /scaffold-mcp del plugin 0.34.0.

## Descubrimientos
- Toda la autenticacion WorkOS del MCP ya esta resuelta en Consultas: APIM validate-jwt (audience = Resource URI) + middleware app (defensa en profundidad) + derivacion org_id/sub -> X-Tenant-Id/X-User-Id. Comandos la replica; no hay decision de seguridad nueva.
- **Colision del PRM en el gateway compartido**: Consultas ocupa {gateway}/api/.well-known/oauth-protected-resource y APIM no admite dos APIs con el mismo path. Salida: RFC 9728 s.3, PRM por resource con path -> api/.well-known/oauth-protected-resource/mcp-comandos. El cliente lee la URL del WWW-Authenticate, no por convencion.
- Verificado en workos.com/docs/authkit/mcp: se admiten multiples Resource Indicators por entorno ("in case you are building multiple MCP servers"); aud sigue el resource pedido. Limitacion: un cliente que omita resource recibe el aud del default (Consultas) y Comandos lo rechaza.
- La system key mcp_extension solo existe tras el primer deploy del codigo con la extension: el issue APIM (#571) depende de que #570 este mergeado Y desplegado, no solo mergeado.
- Contratos HTTP a envolver: POST /api/sedes (codigo*, nombre*, ciudad?, direccion?) y POST /api/colaboradores (9 campos, 6 requeridos); ambos 202 sin body, 400 ValidationProblemDetails, 409 texto .resx.
- Riesgo preexistente, fuera de alcance: los Function Apps de dominio son Anonymous sin restriccion de red y confian en X-Tenant-Id; el MCP les habla por hostname directo. Un MCP de escritura lo hace mas visible. No capturado como issue todavia.

## Decisiones
- fecha_inicio OBLIGATORIA en registrar_colaborador (hecho persistido; migracion con fechas pasadas) -- distinto de fecha_referencia en lectura, que si resuelve "hoy".
- Tras el 202: eco compacto del hecho registrado + nota de visibilidad eventual; sin polling a la ficha (proyeccion Async).
- 409 en colaborador: se devuelve el rechazo del dominio; NO se consolida el reingreso en la tool.
- Capa de identidad: DUPLICAR de Consultas (Rule of Three, segunda aparicion). Senal para extraer: tercer servidor MCP o primer bug que toque ambas copias.
- _meta de tools de comando: readOnlyHint:false, destructiveHint:false (idempotentHint omitido: repetir codigo da 409).
- Suite smoke de Comandos NO entra al grupo smoke-tests-dev: escribe en el event store de tenant-smoke pero no toca Service Bus (MEF-ADR-0048 s.5).
- Corte en 5 issues secuenciales, todos estado:listo (los 4 dependientes con bloqueado): #570 scaffold (tooling, ejecucion manual con /scaffold-mcp) -> #571 APIM (infra) -> #572 identidad AuthKit -> #573 registrar_sede -> #574 registrar_colaborador.
- Glosario: nace la entrada "Servidor MCP de Comandos".

## Descartado
- Extraer la capa de identidad a una biblioteca compartida ahora (contra Rule of Three; queda anotado como senal).
- Default "hoy" para fecha_inicio; consolidar registro+reingreso en una tool; polling a la ficha tras el 202.
- Validar en el worker la lista cerrada de tipos de identificacion o la regla URL-safe (duplicaria reglas del dominio; llegan como 400 traducido).
