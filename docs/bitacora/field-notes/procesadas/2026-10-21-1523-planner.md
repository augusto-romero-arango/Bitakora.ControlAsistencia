## Contexto
Refinar #1110, la vista read-side de la Ventana de entrada (FichaTurno).

## Descubrimientos
- FichaTurno no se reconstruye ante cambios de forma (precedente #607): la forma debe dejar correctas
  las fichas ya materializadas. Modelar el turno fijo como null lo logra sin rebuild.
- HorasYMinutos.ToString() produce "3 h" / "2 h 30 min" (resx con "h" y "min"), no "3 horas".
- La amplitud en minutos se recupera como Cierre - Apertura: no hace falta guardarla en la vista para
  recalcular la ventana cuando cambia la primera franja.

## Decisiones
- FichaTurno gana VentanaDeEntrada? = { Apertura, Cierre, Amplitud }; null = fijo, descanso o sin
  franjas (decision del usuario).
- Amplitud solo como texto (decision del usuario: la vista es para leer; editar usa el PUT de #1106),
  con el formato vigente de HorasYMinutos ("3 h"), aceptado por el usuario.
- HorarioResumido, Descripcion y Completo no cambian.
- #1110 pasa a estado:listo, conserva bloqueado (depende de #1106).

## Descartado
- Solo la amplitud en minutos; ventana siempre presente (exigia rebuild); amplitud estructurada
  { horas, minutos } (precedente ObtenerJornada) y estructurada + texto.
- Cambiar el resx de HorasYMinutos a "horas" (alteraria las descripciones de jornadas).
