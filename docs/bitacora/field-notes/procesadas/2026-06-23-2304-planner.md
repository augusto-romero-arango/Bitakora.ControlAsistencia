## Contexto
El smoke CA-5 (PR #182, HU-181) revento con NullReferenceException al deserializar `DiaCalculado`
(field notes 2026-06-23-1924). Causa raiz: el payload publico llevaba objetos de dominio RICOS
(`IntervaloTemporal`, `DetalleRetardo`) con campos privados que solo serializan bien con el resolver
custom de Marten, resolver que no se aplica al canal de publicacion a Service Bus -> payload lossy.

La sesion partio de una hipotesis del usuario: "no debo traficar objetos de dominio ricos en los
eventos; deberia traficar DTOs planos traducibles". Se valido, se profundizo con perspectiva
downstream (que necesita nomina), y se rediseno el contrato completo nombrando objeto por objeto.

## Descubrimientos
- **Lenguaje ubicuo ya separaba dos terminos** que se habian colapsado en `DesgloseHoras`:
  - "Desglose (de horas)" = el calculo interno por franja/intervalo (dominio).
  - "Discriminacion de horas" / "horas discriminadas" / "tiempo discriminado" = lo que el sistema
    ENTREGA a nomina (glosario lineas 138-140, 253, 282-284). Es el nombre del contrato.
- **El retardo NO es un `Concepto` por razon LEGAL**, no arbitraria: el tiempo no trabajado
  "no genera hora de ninguna categoria" (CST art. 57 num. 4; `docs/referencia/motor_horas_colombia_v2.md`
  linea 83). Los 9 Conceptos son categorias de tiempo TRABAJADO; el retardo es tiempo NO trabajado
  con mecanica propia de compensacion cross-franja.
- **Precedente vivo del patron**: `ControlFranja` (dominio) -> `DetalleControlFranja` (contrato),
  con el aggregate traduciendo (Tell-don't-Ask). `IntervaloTemporal`/`DetalleRetardo` se habian
  quedado como tipos ricos EN el contrato, rompiendo el patron.
- **La perspectiva downstream colapsa el arbol**: nomina consume numeros (minutos por concepto) +
  trazabilidad textual, no geometria temporal. El detalle profundo ya vive en el event store de
  ControlHoras (fuente de verdad auditable); el evento es para PAGAR, no para archivar la prueba.
- "Detalle" NO es una regla de naming: fue una eleccion semantica puntual para la franja. Cada nombre
  se evalua por su significado (correccion explicita del usuario).

## Decisiones
- **Contrato `DiaCalculado` nuevo (100% primitivo)**: `InformacionEmpleado?`, `Fecha`, y
  `HorasDiscriminadas { IReadOnlyDictionary<string,int> MinutosPorConcepto; IReadOnlyList<string> Trazabilidad }`.
- **Granularidad por dia** (no por franja).
- **MinutosPorConcepto = diccionario con CLAVE STRING** (no enum, no lista de renglones): claves =
  `Concepto.ToString()` + clave literal `"Retardo"`. Payload portable a cualquier stack.
- **Enum `Concepto` queda PURO** (9 categorias, sin `Retardo`). Como la clave es string, "Retardo"
  existe solo en el contrato; el dominio no necesita contaminar el enum ni duplicarlo.
- **Trazabilidad** = lista de lineas, una por item con valor, traducida en el back (.resx), viaja
  ya resuelta. Las claves del diccionario son codigo estable (no traducidas).
- **Se elimina `ControlesDeFranja`** del contrato; `DetalleControlFranja` queda huerfano -> se elimina.
  El manejo de anomalias se DIFIERE por completo al flujo de aprobacion (no se hace nada ahora).
- **`DesgloseHoras` (dominio rico) gana `Discriminar() -> HorasDiscriminadas`** (el verbo del glosario).
- **`DetalleRetardo` (rico, mal nombrado) -> `Retardo`**, al dominio. Los demas tipos ricos
  (`IntervaloTemporal`, `MomentoDelDia`, `IntervaloClasificado`, `DesgloseFranja`, `DesgloseHoras`)
  vuelven al dominio sin renombre. `MomentoDelDia` no se contractualiza (concepto interno de calculo).
- **Politica**: "el modelo de dominio rico no cruza el bus" -> ADR local (#186) + draft en Mefisto (#65).

## Descartado
- Parche del bug-investigator (enchufar el resolver de Marten tambien a Wolverine): cura el sintoma
  pero perpetua un contrato no portable. Se prefirio la cura estructural.
- "Detalle" como sufijo/regla universal de DTOs (rechazado: el contrato RESUME, no detalla; "Detalle"
  seria un contrasentido aqui).
- `LiquidacionHoras`/`HorasLiquidables`: el glosario rechaza "liquidacion" (suena a pago; el sistema
  clasifica tiempo, no calcula dinero).
- Lista de renglones `(Concepto, Minutos)` para MinutosPorConcepto: se eligio diccionario string->int.
- Enum de contrato separado (`ConceptoDiscriminado`): innecesario gracias a la clave string.
- Narrar la anomalia en la trazabilidad: el usuario decidio no hacer nada con anomalias por ahora.

## Riesgo aceptado
Al eliminar `ControlesDeFranja` y `FranjasAnomalas`, el contrato pierde toda senal de anomalia.
Un dia con franja anomala se publica con las horas calculables, sin avisar que esta incompleto.
Diferido al flujo de aprobacion/conciliacion (pregunta abierta priority:high de
`docs/eda/flows/calculo-dia-trabajo.yaml`).

## Preguntas abiertas

- Ubicacion final de `Concepto` (Contracts compartido vs dominio) -> se decide en #185.
- Formato exacto de las lineas de `Trazabilidad` -> #184.
