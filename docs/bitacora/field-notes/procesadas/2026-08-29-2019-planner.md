## Contexto
Refinamiento de #502 (servidor MCP de composicion asistida, borrador de la sesion de la manana).
El experto redirigio dos veces: (1) el servidor debe ser remoto y SERVERLESS, no stdio local;
(2) primero se implementa y verifica en ControlAsistencia, y solo despues se deriva la doctrina
a Mefisto -- pero la investigacion debe quedar registrada desde ya porque Mefisto si tendra el ADR.

## Descubrimientos
- **Investigacion verificada** (NuGet API, Microsoft Learn `functions-bindings-mcp`, spec MCP,
  Anthropic "Writing effective tools for agents", Fowler bliki CQS):
  - `Microsoft.Azure.Functions.Worker.Extensions.Mcp` 1.6.0 GA: endpoint `/runtime/webhooks/mcp`
    (Streamable HTTP, SSE deprecado), UN servidor MCP por Function App, system key `mcp_extension`
    por app (header `x-functions-key`). SDK oficial `ModelContextProtocol` 2.2.0 GA (ruta ASP.NET
    Core evaluada y descartada).
  - Spec MCP: servers "highly composable / focused functionality"; `ToolAnnotations`
    (`readOnlyHint`) son hints NO confiables -- la seguridad vive en la frontera del servidor.
  - Anthropic: pocas tools consolidadas, namespacing, respuestas token-eficientes.
  - Todos los endpoints de lectura del BC son `AuthorizationLevel.Anonymous` -> el MCP solo
    necesita base URLs, sin credenciales hacia los dominios.
- **Serverless mata el estado de sesion del servidor**: scale-to-zero + multiples instancias ->
  la tool `fijar_ventana_de_trabajo` se elimina; la ventana vive en la conversacion del cliente.
- **Gap sede-colaborador confirmado en codigo**: Colaboradores no conoce sede; ya existia #465
  ("Asignar la sede natural del colaborador", borrador) que acuña "sede natural".

## Decisiones
- **Granularidad**: un servidor MCP por BC y por PROPOSITO, nunca por dominio (las recetas del
  asistente cruzan dominios; 4 servers = 4 conexiones sin reducir tool count).
- **Particion Consultas/Comandos** (CQS Meyer / CQRS Greg Young): en Functions la key es por
  app -> servidor == credencial == least privilege real. Nombres:
  `Bitakora.ControlAsistencia.Mcp.Consultas` (5a, ahora) / `Mcp.Comandos` (5b/5c, futuro).
- **"Operaciones" rechazado como nombre**: lo propuse sin fuente; el par canonico de la
  literatura es Command/Query.
- `listar_colaboradores` FUERA de alcance hasta terminar colaborador+sede (#465 + proyeccion).
- Sin CA-ADR local: la doctrina se formaliza en Mefisto (MEF-ADR + `/scaffold-mcp`) cuando el
  piloto este verificado end-to-end (#509 es el hito).
- Corte: #508 infra (listo) + #502 codigo (borrador, feature por routing operativo: unico
  pipeline que escribe src/; `## Modelo de eventos` = "No aplica" con encabezado presente) +
  #509 deploy/onboarding (borrador, bloqueado).

## Descartado
- ADR local en el consumidor (decision explicita del experto).
- Ruta ASP.NET Core + Container Apps (mas hosting por construir).
- stdio local como transporte del piloto (reemplazado por remoto serverless).
- Servidor MCP por dominio; servidor mixto lectura+escritura; nombre "Operaciones".
- Tools incrustadas en los Function Apps de dominio (acopla la superficie del asistente al
  deploy del dominio y rompe la disciplina de cliente HTTP puro).

## Preguntas abiertas
- Contrato de `consultar_programacion`: ¿solo rango (recomendacion) o rango + dia puntual?
  Aplazada al refinamiento de #502.
- Forma de los payloads de respuesta de las tools (passthrough vs remodelado token-eficiente).
- Restricciones de la extension MCP por plan de hosting (no declaradas en Learn) -- gate
  anotado en #508.
- Capa de test de composicion del host MCP (¿analogo a MEF-ADR-0029?).
