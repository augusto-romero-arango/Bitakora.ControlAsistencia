## Contexto
El PR #533 (tool `listar_colaboradores` del servidor MCP) reporto dos alertas: tres archivos "sin clasificar" en el coverage gate y un comentario del reviewer que dejo la suite smoke MCP sin extender.

## Descubrimientos
- `coverage_classify_file` (plugin, `_pipeline-common.sh`) no conoce los patrones del proyecto MCP: `*Tool.cs` (logica real, deberia ser `logic` 95%), `*Api.cs` en `/Infraestructura/` (wiring, deberia ser `excluded`), archivos con N records DTO puros (la exclusion exige exactamente 1 tipo por archivo). Ningun gap de tests real: la tool tiene tests unitarios en el mismo PR.
- El argumento del reviewer para no extender la suite smoke ("tests que fallan localmente sin la key de dev") contradice el diseno: el gate del pipeline solo compila los smoke (Stage 2b) y CI resuelve la key `mcp_extension` en runtime por OIDC (MEF-ADR-0048 seccion 4).
- **El PR #533 rompe el smoke existente**: `ComposicionDelHostSmokeTests` pinnea el catalogo exacto con `BeEquivalentTo(4 tools)`; al desplegar se publican 5 -> smoke rojo garantizado post-deploy. El pin exacto de `tools/list` (MEF-ADR-0048 verificacion 2) hace obligatoria la extension de la suite ante toda tool nueva.

## Decisiones
- La extension de la suite smoke se corrige **en el PR #533** via `/fix-review`, no en un issue de seguimiento (el pin roto lo exige). Comentario con el checklist de trabajo publicado en el PR.
- La alerta de cobertura del PR #533 queda resuelta como revision humana confirmada (tool testeada; los otros dos archivos no requieren cobertura).
- Ambos gaps son del plugin -> drafts cross-repo a Mefisto (solo creacion, refinamiento alla).

## Descartado
- Issue de seguimiento en el consumidor para los smoke tests: superado por la correccion en el propio PR.
