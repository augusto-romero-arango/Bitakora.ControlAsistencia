## Contexto
Se perdió noción del estado general del proyecto. La sesión arrancó como backlog para recuperar el panorama completo y derivó en diseño de mejoras al tooling de ejecución batch.

## Descubrimientos
- PRs #66 y #68 (ServiceBus tests + clase base) estaban verdes pero sin mergear desde ayer. Se mergearon durante la sesión.
- Issue #70 tenía label `bloqueado` pero su dependencia (#67/PR#68) ya estaba cerrada. Se desbloqueó.
- `parallel-pipeline.sh`, `batch-pipeline.sh` y `tmux-pipeline.sh` tienen `tdd-pipeline.sh` hardcodeado — el tipo de pipeline ya está en el label del issue, no debería pedirse al humano.
- El skill `/batch` colisiona potencialmente con un built-in de Claude Code.
- `tmux-pipeline.sh` ya tiene `cmd_tooling` y `cmd_infra` para single issue — el patrón de enrutamiento ya existe, solo falta extenderlo a batch y parallel.
- `tooling-pipeline.sh` y `tdd-pipeline.sh` son 100% compatibles: mismo `--status-file`, mismo formato JSON de status, mismo formato `"PR creado: $PR_URL"`.

## Decisiones
- **Enrutamiento automático por label**: los scripts batch/parallel leen `tipo:*` del issue y enrutan al pipeline correcto. Override manual con `--pipeline tdd|tooling`.
- **`tipo:infra` fuera de alcance**: `iac-pipeline.sh` no soporta `--status-file` ni ejecución batch.
- **Función compartida `resolve_pipeline`** en `scripts/_pipeline-common.sh`, sourceada por los tres scripts.
- **Renombrar `/batch` → `/sequential`**: consistente con la convención inglesa del proyecto.
- **Un solo issue (#74)**: los tres scripts comparten archivo y el cambio es mecánico — separarlos crearía dependencias innecesarias.
- Issue #69 (historiador) creado y refinado durante la sesión.
- Issue #72 (soporte tooling en parallel) se cerró por alcance superado — #74 lo reemplaza con alcance más amplio.

## Descartado
- Separar #74 en múltiples issues — los archivos se superponen y el cambio es el mismo patrón repetido.
- `/secuencial` como nombre — el proyecto usa inglés en skills y scripts.
- Soporte de `tipo:infra` en batch — requiere trabajo previo en `iac-pipeline.sh`.

## Preguntas abiertas
- ¿Existe realmente colisión entre `/batch` built-in de Claude Code y el skill personalizado? No se verificó empíricamente.
