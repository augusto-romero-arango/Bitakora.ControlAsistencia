# 2026-10-02 - Ausencias: de una exploracion a doce borradores

> Un dia de preguntas, una a la vez: que es una ausencia, quien la protege y quien manda cuando el bus entrega al reves; mientras tanto, Cosmos 3 aterrizo en main y la sesion de autenticacion se hizo visible.

## Lo que se logro

- **Cosmos 3.x terminado.** Se cerraron #695-#700 (membership id en APIM, MCP, fixtures, ADRs y building blocks a 3.1.0). Continuacion directa del 2026-10-01.
- **Dependabot sin romper el build.** El PR #725 (xunit.v3.mtp-v2 3 -> 4) fallaba con CS0619; #731 lo reemplazo con el bump mas la migracion a `[assembly: Parallelization(Mode = ParallelMode.None)]` y la unificacion de `Programacion.SmokeTests`. #714 (Dependabot mensual) tambien cerro.
- **Sesion de autenticacion visible.** #737 registro la forma del token (sin valores): `sid` presente, access token de 300 s, sin claim de nombre de organizacion, AuthKit publica `introspection_endpoint` pero no `revocation_endpoint`. #735 (`obtener_sesion`, PR #739) y #736 (`cerrar_sesion`, PR #740) quedaron implementados, con `cerrar_sesion` devolviendo la URL publica de logout de WorkOS.
- **Ausencias modeladas y desglosadas.** Tras una exploracion de 13 decisiones se registro CA-ADR-0036 (#741, PR #753) con 10 decisiones de dominio y 3 de arquitectura, sin nombrar clases ni endpoints. Se refinaron #741-#752, #754-#756, y se implementaron en el dia: #742 (topics, PR #757), #743 programar (PR #758), #745 solicitud respeta ausencias (PR #759), #746 asignar al ControlDiario (PR #760), #747 cancelar y restablecer (PR #761), #748 clasificar el dia (PR #762), #749 AsistenciaDiaria (PR #763), #750 ausencias de un colaborador (PR #764) y #751 tools MCP (PR #765).
- **#651 refinado** a listo con 7 CAs: el turno inline en la plantilla semanal, con nombre derivado de la franja en `NotacionFranja.Rango`.

## Problemas encontrados

- xunit 4 marca `DisableTestParallelization` con error; afectaba 5 smoke tests. No esta verificado que v4 siga respetando `parallelizeTestCollections` en `xunit.runner.json`; el issue lo esquiva unificando el mecanismo.
- **El conector de comandos en claude.ai no autentica.** Sospecha principal: el Resource Indicator `.../mcp-comandos` no esta dado de alta en WorkOS (o el token trae `aud` de consultas). Pendiente de evidencia del humano.
- **Hueco detectado:** `TurnoVigente` no conocia ausencias y, de paso, ignoraba `TurnoDiarioCancelado` (bug preexistente, corregido dentro de #756 por decision del experto).
- **Orden del bus:** la cancelacion de una ausencia puede llegar antes que la ausencia; por eso el dia recuerda las ausencias canceladas.
- El experto corrigio dos veces el rumbo: los ADR no llevan detalles de implementacion, y turno sobre turno sigue siendo "el ultimo gana".

## Lo que descartamos

- Ausencia como turno del catalogo; ausencia que reemplaza al turno; replica de dias aprobados en Programacion (MEF-ADR-0046; ControlHoras archiva la ausencia tardia); aprobacion de ausencias; datos estructurados por motivo (dato sensible).
- `POST /sessions/revoke` para `cerrar_sesion`: exige custodiar la API key de poderes totales en un servidor MCP y no limpia la cookie de AuthKit.
- Ignorar versiones mayores de xunit en Dependabot: solo aplaza el problema.
- Default "desde hoy" en la consulta de ausencias de un colaborador (rango obligatorio); mostrar el turno cubierto en el dia de ausencia; bloquear la aprobacion de un dia de ausencia con marcaciones; registrar las fechas respetadas en el evento.
- Prefijo en el nombre derivado del turno inline, y recortar el caso "homonimo vacio" para bajar a 6 CAs (dejaba un bloqueo permanente por reintento).

## Aprendizajes

1. Explorar una pregunta a la vez con el experto produce decisiones que sobreviven el desglose; el ADR registra el "que", los issues el "como".
2. Si el bus puede reordenar, el modelo debe recordar lo cancelado, no confiar en la entrega.
3. Medir antes de disenar: #737 respondio con el token real lo que la especificacion MCP no decia.
4. Abiertas: Permiso (por horas), incapacidad durante vacaciones (nomina), si ambos conectores comparten `sid`, y la asignacion de plantilla semanal a colaborador.
