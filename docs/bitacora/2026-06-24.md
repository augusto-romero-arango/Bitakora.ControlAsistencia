# 2026-06-24 - El Bus No Habla Dominio

> La noche del 23 reveló que los tipos ricos del dominio se colaban en el contrato de DiaCalculado; el 24 fue la ejecución del rediseño: tres issues cerrados en serie, un contrato 100% primitivo vivo en main, y un falso positivo del harness que asustó sin razón.

## Problemas encontrados

**El gate de refactoring del harness abortó el pipeline con un falso positivo**

El Stage 3 del pipeline TDD de #185 reportó:

```
Tests post-refactoring: 87 (baseline: 214)
✗ ERROR: El refactoring perdió tests: antes=214, después=87
```

La investigación (field note 12:48) reveló el bug en `extract_test_count()` del harness: usa `head -1` sobre el output combinado de todos los proyectos, capturando solo el conteo del **primer proyecto alfabético** (`Contracts.Tests`). El refactor de #185 movió exactamente 127 tests de `Contracts.Tests` (214→87) a `ControlHoras.Tests` (169→296). El total global: 425 = 425. Ni un test se perdió.

Verificación triple: `git diff --name-status -M` mostró solo renames (R), ningún delete (D) huérfano; `dotnet test --list-tests` en ambos lados dio 422 nombres totalmente calificados idénticos (tras normalizar namespace y tipo renombrado); el único archivo `A` fue `IgualdadTestBase.cs`, un helper nuevo que suma. El pipeline abortó sin crear PR. El PR fue creado manualmente desde el worktree y mergeado. El bug es genérico del harness — afecta a cualquier consumidor con más de un proyecto de tests donde el primero alfabético pierda tests por movimiento legítimo.

## Lo que descartamos

**Parchear el bug enchufando el resolver de ADR-0015 también a Wolverine** — cura el `NullReferenceException` pero perpetúa un contrato no portable: cualquier consumidor en otro stack no podría deserializar los tipos ricos. La cura estructural (tipos primitivos en el contrato) es la única opción que hace el evento verdaderamente público según ADR-0002.

**`LiquidaciónHoras` / `HorasLiquidables`** como nombre del nuevo contrato — el glosario rechaza "liquidación" (suena a pago; el sistema clasifica tiempo, no calcula dinero).

**Lista de renglones `(Concepto, Minutos)`** para MinutosPorConcepto — se eligió diccionario `string→int` por portabilidad cross-stack y porque la clave literal `"Retardo"` no cabe en el enum sin contaminarlo.

**`ConceptoDiscriminado`** como enum de contrato separado — innecesario gracias a la clave string: `"Retardo"` existe en el contrato sin necesitar un tipo propio.

**Narrar anomalías en la Trazabilidad** — diferido al flujo de aprobación/conciliación. Riesgo aceptado: un día con franja anómala se publica con las horas calculables sin señal de que está incompleto.

## Aprendizajes

1. **Un tipo con campos privados y resolver custom no puede cruzar el bus como contrato público.** El bug durmió hasta que `DiaCalculado` llevó su primer `IntervaloTemporal` real. El patrón correcto es el que el dominio ya tenía: el aggregate traduce el modelo rico a un DTO 100% primitivo antes de publicar — `ControlFranja → DetalleControlFranja`. Los tipos ricos habían salido al contrato sin que nadie lo notara porque el camino feliz (con `DesgloseHoras.Vacío`) nunca los ejercitaba.

2. **Un gate de refactoring que compara solo el primer proyecto alfabético no detecta movimientos de tests entre proyectos.** El bug de `head -1` en `extract_test_count` hace que cualquier refactor que saque tests del primer proyecto dispare un falso positivo. Simétricamente: una pérdida real en un proyecto no-primero quedaría silenciosa. El fix correcto suma todos los proyectos, no solo evita el `head -1` del primero.

3. **El lenguaje ubicuo del dominio ya tenía la respuesta.** El glosario diferenciaba "Desglose (de horas)" (cálculo interno) de "Discriminación de horas" / "horas discriminadas" (lo que se entrega a nómina). El contrato se llamaba `DesgloseHoras` cuando debía llamarse `HorasDiscriminadas`. Cuando el nombre del contrato refleja el lenguaje del consumidor downstream, el diseño se vuelve obvio.

4. **"Retardo" no es un Concepto — es una mecánica.** El tiempo no trabajado no genera ninguna categoría de hora (CST art. 57 num. 4). Colapsar retardo y conceptos de tiempo trabajado en el mismo enum hubiera sido una mentira en el modelo. La clave literal `"Retardo"` en el diccionario lo trata como lo que es: algo con mecánica propia que el contrato debe nombrar sin mezclar con las categorías de tiempo trabajado.
